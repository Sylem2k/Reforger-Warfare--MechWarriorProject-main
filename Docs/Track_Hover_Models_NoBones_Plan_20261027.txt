HOW I PLAN TO MAKE THE TREADS MOVE
The current sample track is one static joined mesh that includes skirt, wheels, tread belt and tread ribs. No script can spin only the wheels of a single baked mesh simply by rotating the whole attached part. I must go back to the procedural Blender generator BEFORE join_as_one() and separate the moving geometry:
1. Keep armor skirt, suspension frame and mount fixed.
2. Give each road wheel its own rotatable mesh and a bone or dedicated child entity with pivot through the axle (X axis).
3. Make the rubber tread its own UV-unwrapped belt, with seamless UV coordinate around its oval route. If Workbench supports an appropriate scrolling material shader, animate the tread UV locally based on speed; otherwise build a true animated bone/tread-link rig + animation graph.
4. For tank-steering behavior use left/right speed = forward_speed +/- yaw_rate_rad_per_sec * (distance_between_tracks / 2). Rotate wheels at speed / radius. Reverse direction and spin tracks opposite ways on pivots. Derive visually from the replicated root transform on each client instead of per-link network RPCs.
5. Arma Reforger will NOT automatically play Blender keyframes on an arbitrary imported XOB. I need to wire a supported Enfusion animation graph/instance and a suitable controller or shader. No rig or actual tread animation has been committed in this pass.
