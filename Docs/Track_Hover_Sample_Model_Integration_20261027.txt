IMPORTANT TRACK ANIMATION NOTE
The initial Blender generator joined ALL model geometry — belt, tread ribs, road wheels, hull plates and mounting socket — into one static mesh per XOB. No wheel bones, animated texture, animation graph or animation instance were imported. Attaching the XOBs makes the track pods move with the chassis, but neither road wheels nor tread belts spin visually.

For the real moving-tread version I should use the original Blender generator as my modeling source, BEFORE its join_as_one() step, to preserve independent pieces:
1. Keep armored frame/socket/skirt static.
2. Extract four road wheels (plus their axle caps) as animatable wheel meshes, or bind each to wheel bones about the lateral X axle.
3. Keep the rubber belt visually separate. Prefer a seamless UV layout around the oval belt, with scroll driven by the real observed track speed IF a verified Enfusion material shader supports scrolling. Otherwise rig a smaller number of tread links and animate their translation around the closed oval path in an Enfusion-supported animation graph.
4. Left and right tracks must turn at different speeds. Forward/backward motion drives both the same, and hull pivot adds/subtracts speed; turning in place runs treads in opposite directions.
5. Animate visual wheels/treads on each client using the replicated mech root speed/turn rate, without new step RPC messages. The current chassis is already server authoritative.
6. Export rigged FBX for Workbench and implement a proper animation graph or verified UV scroll shader; do not assume a Blender F-curve or UV animation will automatically play in Arma Reforger.
7. For now, moving-track SOUND_MECH_TRACK_CLANK and SOUND_MECH_TRACK_RUMBLE provide audio feedback even with static tread geometry.

HOVER PAD VISUALS
Hover pads don't need bones to move with the vehicle. To make hover feel alive, give the models appropriate emissive material and local thruster exhaust particles plus ground dust driven by the existing movement/clearance state. The imported CGS_Hover_Cyan_Emission.emat material currently contains only an empty MatPBRBasic declaration, so no emission setup has been validated.
